# Radix bitmap 第二阶段：诊断与减少写入开销

## 目标、边界与隔离

从 R6（58b7d1f 的算法）继续优化完整 int32 set，仍在 benchmark/btree_set；独立工作树 codex/radix-bitmap-layout。保持重复/缺失语义、size、有符号 lower_bound、回收与异常安全。作者实现、输入、基线计时和 ISA 选项不改。不将初始化/预分配移出计时后声称加速；不进入 main。

## 诊断与阶段

1. perf_event_paranoid=4 阻止硬件事件，记录该限制，不修改内核权限。独立诊断构建统计页/叶分配、移动字节、前缀更新、转换，统计不编译进正式 benchmark；不能据此声称 CPU 时间占比。
2. 重跑 R6 作为本阶段基线，并保持三规模、五操作、四容器、5 次重复、0.1s、random interleaving、CPU 8 的既有口径。
3. R7 尝试页内分组叶：让 rank、移动只作用于局部组，取消全页前缀维护。数据路径依诊断结果确定，保留完整四层位图语义。每轮先正确性/ASan，再相同 benchmark，另测 radix 10M。
4. 依据结果继续一到两轮，重点为小额分配/页布局/内联与局部增长策略；没有收益的方案也记录，不混入最终版本。涉及页池时记录保留内存、构造成本和回收规则。
5. 最终独立审查所有权、紧凑/稠密转换、索引和位边界、分配失败发布顺序；记录最终取舍、所有轮次、源代码及环境，只推送 benchmark。

## 验证、风险与回滚

原有19项测试和既有R6性能构成修改前证据。为新布局增加边界/组扩容/降级/复用验证。每轮独立提交，可恢复此前布局；正式机器仍仅sz_45/9950X，本机只验证功能。存储统计需包含实际容量与空闲保留；不要将诊断时间放入结果。局部组可能增加元数据、分支、分配和缓存压力，故同时比较百万与千万规模。未对外部依赖全面 sanitizer 重编译。

## 结果

已完成R6重测及R7/R8/R9三轮优化。R7局部分组减少搬移却恶化查询/大规模操作，撤回；R8计时内按需256页slab分配及R9有效位保护的稠密叶按需初始化保留。百万插入18.97→18.02、命中9.05→8.56、删除24.67→21.90 ns/op；十万删除26.53→15.15；千万插入39.78→34.53。1K未命中补测约慢10.3%，历史R0部分退步仍在，均已列出。

四轮共1300条主测、160条补测验证有效，每轮均先Release/CTest/ASan/UBSan。最终76c10f0在Linux通过22项set测试、CTest3/3、ASan/UBSan填充值165与255；本机完整构建、19项set测试/CTest3/3通过。完成对象生命周期、异常发布顺序、稠密未初始化槽读保护和空闲池容量核算审查。源代码、JSON和日志保存在sz_45专用tmp目录，默认nova/vcpkg checkout未改。完整结果见benchmark/btree_set/LAYOUT_OPTIMIZATION.md及RESULTS.md；只集成并推送benchmark，不进入main。

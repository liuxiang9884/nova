# Radix bitmap 多轮优化

## 目标与边界

在 benchmark 分支对实验 set 进行至少三轮可复现的优化和比较，降低全 int32 随机键场景的插入/删除成本及内存。保持完整有符号域、重复/缺失操作语义、size、lower_bound 和空页回收，不改作者 B-Tree、数据生成或基线计时。不承诺复现作者未公开代码的十倍收益。

## 计划与设计决策

1. R0：在 sz_45 CPU 8 重跑当前实现，作为本轮基线；先保留原始 JSON 与源码提交。
2. R1：8+8+8+8 位图页延迟初始化，仅初始化首次使用的叶块；检查未初始化读和摘要有效位。
3. R2：尝试 8+8+10+6，页内用存在位图 + popcount rank + 紧凑 64 位叶数组，减少随机稀疏键下的内存占用；真实插入期间分配和移动仍计时。
4. R3：单独测试前缀计数，减少查询 rank 的 popcount 次数。R4：另外测试 16 个叶字内联存储，避免将 rank 与分配变化混为一轮；按实测取舍。
5. 每轮先跑正确性及 ASan/UBSan，再以同一 Google Benchmark 驱动比较全部四种容器。三个规模（1K/100K/1M）、五种操作、五次重复、0.1s 目标计时，记录版本、环境、CPU ns/op、方差和存储。不得将构造中的准备工作移出计时后冒称操作加速。
6. 最后一次布局在 10M 全部五种操作上做检查；对优势/退步作最终审查，选择保留版本，更新中文文档与每轮机器可读数据，仅合入/推送 benchmark。

## 验证与风险

既有测试和历史性能构成修改前证据。增加针对未初始化页重用、跨叶/摘要边界、紧凑数组中间插入/删除/扩容及随机 lower_bound 的验证。回收后的内存计数必须恢复；分配异常必须先于发布有效位；禁止越界移位、悬空引用及错误 rank。依赖未全量 sanitizer 重编译的限制保持说明。

各轮独立提交，可回退任一轮；无需主线迁移。只在指定 sz_45/9950X 测性能，本机限于构建和正确性。重复测量不是隔离系统，不能根据小于方差的差异宣称胜负。作者表与原测试环境/数据/统计不同，仅作为背景目标。

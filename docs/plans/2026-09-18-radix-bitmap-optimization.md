# Radix bitmap 多轮优化

## 目标与边界

在 benchmark 分支对实验 set 进行至少三轮可复现的优化和比较，降低全 int32 随机键场景的插入/删除成本及内存。保持完整有符号域、重复/缺失操作语义、size、lower_bound 和空页回收，不改作者 B-Tree、数据生成或基线计时。不承诺复现作者未公开代码的十倍收益。

## 计划与设计决策

1. R0：在 sz_45 CPU 8 重跑当前实现，作为本轮基线；先保留原始 JSON 与源码提交。
2. R1：8+8+8+8 位图页延迟初始化，仅初始化首次使用的叶块；检查未初始化读和摘要有效位。
3. R2：尝试 8+8+10+6，页内用存在位图 + popcount rank + 紧凑 64 位叶数组，减少随机稀疏键下的内存占用；真实插入期间分配和移动仍计时。
4. R3：单独测试前缀计数，减少查询 rank 的 popcount 次数。R4：另外测试 16 个叶字内联存储，避免将 rank 与分配变化混为一轮；按实测取舍。R5：在既有 AVX2 编译条件下将 16 路前缀更新向量化，保留便携标量后备，单独验证计数维护开销。R6：R5 在 10M 密集页下出现约 2 倍插入/删除退步，因此增加 64 个非空叶字后的按页稠密转换；转换成本计入插入，并复测 1M 与 10M。
5. 每轮先跑正确性及 ASan/UBSan，再以同一 Google Benchmark 驱动比较全部四种容器。三个规模（1K/100K/1M）、五种操作、五次重复、0.1s 目标计时，记录版本、环境、CPU ns/op、方差和存储。不得将构造中的准备工作移出计时后冒称操作加速。
6. 最后一次布局在 10M 全部五种操作上做检查；对优势/退步作最终审查，选择保留版本，更新中文文档与每轮机器可读数据，仅合入/推送 benchmark。

## 验证与风险

既有测试和历史性能构成修改前证据。增加针对未初始化页重用、跨叶/摘要边界、紧凑数组中间插入/删除/扩容及随机 lower_bound 的验证。回收后的内存计数必须恢复；分配异常必须先于发布有效位；禁止越界移位、悬空引用及错误 rank。依赖未全量 sanitizer 重编译的限制保持说明。

各轮独立提交，可回退任一轮；无需主线迁移。只在指定 sz_45/9950X 测性能，本机限于构建和正确性。重复测量不是隔离系统，不能根据小于方差的差异宣称胜负。作者表与原测试环境/数据/统计不同，仅作为背景目标。

## 结果

- 完成 R0 基线和 R1–R6 六轮优化，各轮独立提交；每轮都跑完整四种容器，7 × 60 × 5 = 2,100 条正式原始记录均有效，CPU/N 与计数器逐条一致。
- 新测试先在修改前版本通过，原有性能数据作为优化前证据。最终保留 R6（`1d05f77`）；审查追加稠密页收缩后重插测试（`27a78dc`），不改测量代码。
- 每轮 sz_45 Release 完整构建、CTest 3/3 与 ASan/UBSan 通过；最终 19 项正确性通过，本机标量后备 16 项通过。覆盖紧凑/稠密转换、失效前缀不得读取、扩容、所有位边界、有符号 lower_bound 与回收。
- 百万键 R0→R6：插入 100.93→18.94 ns/op，命中 12.22→9.11，未命中 12.28→1.87，混合 12.23→8.81，删除 43.86→24.60；内存 514.51→25.62 MiB。
- R5 的千万键退步促成 R6 自适应页：R0/R5/R6 分别做 25 次大规模测量，共 75 条有效记录。R6 修复大部分退步，但千万插入仍比 R0 慢约 40%，命中约慢 12%，存储约 532 MiB；已明确保留取舍。
- R6 十万未命中有一次慢样本，未删除。另对四种实现补测 0.2s × 10 次，共 40 条记录，radix 中位数 2.211 ns/op、CV 1.89%，与主表 2.231 接近，不替换原表。
- 最终独立审查检查了摘要/rank 同步、16 位前缀范围、SIMD 访问范围、内存移动边界、分配异常先于状态发布、RAII、稠密状态转换与计时范围；完成对应回归。数据、源码版本、日期和原始结果位置见 `benchmark/btree_set/OPTIMIZATION.md`。
- 仅集成和推送 benchmark，无 main PR；原版及每个中间方案均可按提交恢复。

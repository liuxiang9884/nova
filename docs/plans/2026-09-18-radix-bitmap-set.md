# 四层 radix bitmap set 与 benchmark

## 目标与边界

在 `benchmark/btree_set` 增加自主实现的 `int32_t` radix bitmap set，比较 Abseil、作者 AVX2 B-Tree、STL 与新实现；不修改作者算法，不声称复现作者尚未公开的 radix 实现，不进入 main。

## 设计决策

- 按有符号顺序将键 XOR 符号位，采用 8+8+8+8 四层占用位图。前三层汇总非空子范围，第四层表示键是否存在。
- 高 16 位直接索引 65,536 个页指针，页按需分配；每页包含第三层 256 位摘要和第四层 65,536 位数据。前两层摘要常驻。成员查询直接访问页与叶位图；lower_bound 利用全部摘要跳过空范围。
- 完整 32 位值域，不依赖键集中在小范围。支持插入、成员查询、删除、size、lower_bound；不提供 STL 迭代器、复制、移动或并发访问保证。
- 空页立即释放，允许无限次有界规模的增删；采用 RAII 管理页。构造指针表不计入既有计时口径，首次插入的页分配/清零和删除的页释放均计时。
- 该布局刻意选择直接索引以降低查找指令数。均匀随机键会覆盖几乎所有页，容量可到约 515 MiB；必须披露内存及插入代价，不能只报告查询提速。

## 实施与验证

1. 隔离工作树；先添加 API 缺失的编译失败证据与完整域/边界/随机交错/有序查找测试。
2. 实现集合、接入同一 Google Benchmark 驱动，保持三种基线的行为与随机数据不变。
3. 本机构建及正确性检查；sz_45 上四种实现的 Release 正确性检查和 ASan/UBSan。
4. sz_45 Ryzen 9 9950X CPU 8 运行四种实现、五种操作、三个规模、五次重复，使用同次运行的中位数比较；10M 用例做大规模正确性 smoke。记录代码版本、依赖、标志、原始 JSON、内存口径与限制。
5. 单独进行完整 diff 和错误路径审查，修复发现；更新中文文档与结果，合入并推送 benchmark，不创建 main PR。

## 回滚与风险

回滚本次实验提交即可。性能依赖页覆盖率、缓存和 allocator；512 MiB 级内存应先确认测试机余量。摘要同步、符号顺序、跨 64/256/65,536 边界和清空后重插为主要正确性风险。分配失败必须不改变集合的可观察状态。

## 结果

- 测试先行：新测试在实现前编译失败，原因是 `radix_bitmap_set.hpp` 不存在。
- 本地 AppleClang Release：13 项正确性测试通过；作者 AVX2 实现按平台条件排除。
- 其余结果待 sz_45 验证后填写。

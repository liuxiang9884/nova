# Radix bitmap 的六轮优化

本记录包含一次本轮基线 R0 和六轮独立优化 R1–R6。每一轮都先通过正确性/ASan/UBSan，再在 **sz_45 / Ryzen 9 9950X / CPU 8** 运行全部四种容器的同一组 benchmark。最终保留 R6，全部实验只在 `benchmark` 分支。

计时口径完全沿用原实验：互异完整域 int32，固定插入/命中/未命中/混合/删除序列，0.1s 目标计时、5 次重复、中位数、random interleaving，Release `-O3 -DNDEBUG -mavx2 -mpopcnt`。各轮数据生成、作者算法、Abseil/STL 和主计时循环未变。构造时只有常驻目录，所有页/叶分配、初始化、扩容、紧凑数组移动都在插入/删除计时内，没有通过移出计时区间制造加速。存储诊断在计时前完成。

编译器 GCC 13.3.0，Abseil 20260107.1#3，Google Benchmark 1.9.5，manifest baseline `114d9fe62faf35856b45cf55cb93b57028a45d63`。CPU 8 所在 CCD 的 L3 为 32 MiB，SMT 同胞为 CPU 24。保留 powersave/scaling/ASLR 设置；没有整核隔离。不同轮次分开执行，不同时运行构建或其他本任务性能程序。

## 每轮判断

- **R1：只解决了一部分初始化浪费。** 百万未命中查询从 12.28 降到 2.70 ns/op，因为摘要可以在访问叶块前拒绝大部分不存在的键；但命中查询增加摘要读取/判断，百万命中从 12.22 升到 14.21。分配容量仍为约 515 MiB，十万插入仍需 438.46 ns/op。
- **R2：紧凑存储是本轮最主要的改进。** 百万内存降至 20.67 MiB，插入降至 28.72 ns/op，删除降至 27.79；十万插入从 R0 的 604.60 降至 27.97。代价是每次命中需计算 rank，十万命中/混合查询退步，证明不能只看内存和插入。
- **R3：前缀计数改善查询，增加写入维护。** 百万命中从 12.52 降至 8.54，混合从 12.09 降至 8.28，但插入回升到 35.99、删除 36.86。32 字节/页的前缀占用使百万存储增加 2 MiB。
- **R4：内联叶减少小额分配。** 百万插入恢复至 28.83，删除 32.60；内存从 R3 的 22.67 增至 25.12 MiB，百万命中略慢至 8.96。它保留内联空间，即便页已溢出，因此空间并非零成本。
- **R5：向量化降低前缀维护成本。** 百万插入降至 18.89，删除降至 23.49；存储布局与 R4 相同。百万命中/混合为 9.45/8.77，未比 R3 快；R5 对插入、删除、查询和内存作出取舍，但后续千万键复测暴露了密集页的退步。
- **R6：按页密度自适应，减少大规模移动。** 稀疏页沿用 R5，第 65 个非空叶字插入时转换为 1,024 字的直接索引位图，转换和清零全部计时。百万插入 18.94、删除 24.60，内存 25.62 MiB；千万删除从 R5 的 61.40 降到 27.14。代价是千万容量增加到约 532 MiB，且千万插入仍慢于原版。最终保留 R6 作为跨规模折中；没有实现一个对所有负载都占优的版本。

R0→R6 百万键：插入耗时约降 81.2%，删除约降 43.9%，未命中约降 84.8%；容量从 514.51 降到 25.62 MiB，约少 95.0%。小规模命中和混合查询有实质退步，例如十万混合从 2.65 升至 6.46 ns/op，已经完整列出。

以上原因是结合代码变化和实测的解释，未用硬件计数器定量拆分 allocator、cache miss 和指令周期。原始 JSON 含每次测量；R0–R5 最大 CPU 变异系数依次为 10.12%、9.57%、9.83%、9.93%、6.92%、7.09%，不能据微小差异断言胜负。R6 最大 CV 为 36.04%，来自 radix 十万未命中查询：五次为 2.215、4.369、2.231、2.229、2.238 ns/op，保留全部原始值和中位数 2.231，没有删除离群记录；另以相同四种实现、0.2s × 10 次补充复测，radix 中位数 **2.211 ns/op、CV 1.89%**，与主表中位数接近；这 40 条记录不替换主表，摘要见 [optimization-supplement.csv](optimization-supplement.csv)，原始 `r6/miss-100k-supplement.json` 保留。

## 千万键补充比较与剩余退步

发现 R5 密集页问题后，对 R0/R5/R6 各做五种操作 × 五次重复，使用相同 CPU、数据与计时口径。这 75 条记录独立于三个标准规模，全部计数验证通过。摘要见 [optimization-large.csv](optimization-large.csv)。

| ---: | --- | ---: | ---: | ---: |
| 10,000,000 | insert | 28.51 | 60.40 | 39.85 |
| 10,000,000 | find_hit | 12.42 | 21.22 | 13.92 |
| 10,000,000 | find_miss | 12.43 | 8.21 | 7.75 |
| 10,000,000 | find_mixed | 12.42 | 15.48 | 12.30 |
| 10,000,000 | erase | 28.19 | 61.40 | 27.14 |

R0/R5/R6 的存储依次为 **514.51 / 140.15 / 532.01 MiB**；三组最大 CPU CV 分别为 0.85%、1.60%、0.67%。R6 解决了 R5 大部分密集页操作退步，删除回到原版水平附近；但插入仍比 R0 慢约 40%，命中查询约慢 12%。百万键的约 25 MiB 不能外推成千万键也只需类似容量。读密集或内存紧张的具体负载应根据这些版本取舍。

## 验证与归档

- R0 为 16 项 set 正确性测试；R1 增加重用页/空叶可见性测试后为 17 项；R2–R5 增加紧凑数组扩容、中间删除和所有 1,024 个叶索引对照后为 18 项；R6 增加稠密转换测试后为 19 项。
- 每轮 sz_45 完整 Release 构建、CTest 3/3、ASan/UBSan + leak 检查均通过。sanitizer 设置还用 `malloc_fill_byte=165` 辅助暴露错误的有效位访问；ASan 本身不作为未初始化内存检测器宣称。
- R1–R6 本机 AppleClang Release 正确性检查通过，最终 16 项；这是标量后备路径的功能验证，不混入指定机器的性能结果。
- 最终检查了位图/紧凑叶/rank 前缀一致性，最多 1,024 个叶字的 16 位计数范围，0/63/64/255/256/1023/1024 边界，SIMD 32 字节无越界访问，扩容异常先于状态发布，RAII 所有权及空页回收。保持完整有符号 `lower_bound` 对照测试。
- 最终审查新增稠密页收缩后重新插入所有空叶的验证（`27a78dc`），确保不读取失效前缀；独立 final-verify 构建中 Release/CTest 和 ASan/UBSan 的 19 项均通过。此提交只改测试，测量算法仍为 `1d05f77`。

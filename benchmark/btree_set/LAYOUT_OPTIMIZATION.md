# Radix bitmap 第二阶段：R7–R9

本次保留 R8 页池和 R9 按需初始化稠密叶，撤回 R7 分组布局。所有性能数据来自 **sz_45 / Ryzen 9 9950X**，实验只进入 `benchmark`。前六轮保留在 [OPTIMIZATION.md](OPTIMIZATION.md) 和 [RESULTS-R6.md](RESULTS-R6.md)。

## 方法与版本

重测 R6 后，每轮先完整 Release 构建、CTest 3/3、ASan/UBSan，再运行四种 set × 1,024/100,000/1,000,000 × 五操作 × 五次重复；另测 radix 的 10,000,000 五操作，每项五次。固定 CPU 8、每次目标 0.1s、random interleaving、CPU ns/op 中位数。共 1,200 条标准规模和 100 条千万规模原始测量；另有 160 条方差补测。没有丢弃慢样本。

硬件/依赖/数据集/计时边界与 [README.md](README.md) 一致：9950X，GCC 13.3.0，Release `-O3 -DNDEBUG -mavx2 -mpopcnt`，Abseil 20260107.1#3，Benchmark 1.9.5。页池首次分配、初始化、稠密转换、叶搬移、删除和最终清空池均在对应操作计时内。作者的节点池仍在构造时分配并排除，不改变原比较口径。

| 轮次 | 被测源码 | 改动与取舍 |
| --- | --- | --- |
| R6 重测 | `14c1f2799132e7eff8547692242bfe4c40b49a9d` | R6 算法，加独立诊断目标；正式计时未启用计数器。 |
| R7 | `8ffda8e17f462f2adef8b823871c8c186eedbac2` | 第三层拆成16个局部64字组，每组内联2字；去掉全页前缀和跨组搬移。未采用。 |
| R8 | `e5aaa4200aa0edaca1d4ee907fabc534dc99b3d1` | 恢复R6紧凑页；按需分配256页一组的slab，空页槽复用。采用。 |
| R9 | `e1aaeaaecf43ce112d920e9a9dd3918a4801e3c8` | 基于R8，稠密页只初始化占用叶，全部读取由位图有效位保护。采用。 |

## 先统计结构开销

机器的 `perf_event_paranoid=4` 禁止硬件事件；没有修改系统权限。新增独立 `nova_radix_diagnostics` 统计实际操作，计数宏在正式 benchmark 中为空。这些数据不是耗时分解，不能推导 CPU 周期占比。

百万规模插入：

| 布局 | 逻辑页数 | 页存储分配次数 | 叶分配次数 | 移动字节 | 前缀更新 |
| --- | ---: | ---: | ---: | ---: | ---: |
| R6 | 65,536 | 65,536 | 22,985 | 30,054,080 | 992,516 |
| R7 | 65,536 | 65,536 | 76,505 | 1,229,016 | 0 |
| R8/R9 | 65,536 | 256 | 22,985 | 30,054,080 | 992,516 |

R7 达到了减少搬移的目的，但分配次数和页元数据增大，百万查询与千万全部操作反而更慢。不能只凭搬移量判断收益，因此撤回。

R8 把逐页分配改为块分配，保留R6较紧凑的布局。R9 在千万规模的65,536次稠密转换中省去512 MiB整块清零；仍逐个写入已有叶和新增叶。这是源码中移除的清零范围，非硬件计数器测得的内存总流量。占用位清除后的叶不能读取，再插入时完整覆盖，不能依赖malloc恰好返回零。

R9 相比 R6 重测，百万插入/命中查询/删除耗时分别降低 5.0% / 5.5% / 11.2%；十万删除降低 42.9%；千万插入降低 13.2%。

R9 相比 R8 的主要收益是千万插入降低 8.8%；其他小规模差异混有代码布局、allocator状态及运行波动，不能全部归因于稠密初始化，因为百万测试根本没有触发转换。R9的1K插入、未命中，以及部分十万/百万项也有比R8慢的结果，表中全部保留。

历史退步仍在：相对第一阶段R0，十万混合查询2.65→6.28、千万插入28.51→34.53、千万命中12.42→13.33 ns/op。不能将本阶段相对R6的改善说成全面超过所有旧版本。

## 方差补测

标准规模最大CV：R6重测40.76%（十万未命中）、R7 10.66%（十万插入）、R8 24.80%（十万未命中）、R9 6.79%（1K未命中）。千万规模各轮最大CV≤2.21%。不修改 governor/ASLR、不隔离整核、不主动清cache。对R6和R9的1K/十万未命中，以四种实现各10次补测，主表不替换；[layout-supplement.csv](layout-supplement.csv) 保留完整统计。

| 轮次 | N | 未命中 ns/op | CV |
| --- | ---: | ---: | ---: |
| r6b | 1,024 | 0.457 | 1.70% |
| r6b | 100,000 | 2.209 | 0.62% |
| r9 | 100,000 | 2.141 | 0.55% |
| r9 | 1,024 | 0.504 | 0.40% |

1K未命中补测中R9由0.457升到0.504 ns/op，约慢10.3%；主表的微小领先未复现，不将它列为优化收益。

## 容量与回收语义

| N | R6 MiB | R7 MiB | R8/R9 MiB |
| ---: | ---: | ---: | ---: |
| 1,024 | 0.811 | 0.897 | 0.813 |
| 100,000 | 15.773 | 20.083 | 15.820 |
| 1,000,000 | 25.619 | 27.843 | 25.621 |
| 10,000,000 | 532.008 | 537.508 | 532.010 |

容量包括对象、slab指针数组容量、所有slab槽（活跃与空闲）和活页叶数组；不包括allocator自身元数据/保留内存，也不是RSS。R8/R9一百万键容量约25.62 MiB，千万仍约532 MiB，并未解决稠密布局的大规模空间开销。

空页销毁时叶数组立即释放，但slab保留到整个集合为空或析构。持续删到只剩少量键时，页池仍可能保留历史峰值的约20 MiB页存储；没有把这些空闲槽从容量统计中藏掉。页槽复用降低分配次数的代价就是延迟归还slab。

## 正确性与审查

R7在Linux通过20项set测试，R8/R9通过21项；最终另补非空池析构测试，覆盖同时存活的紧凑堆叶、稠密叶及已释放槽。最终测试提交 `76c10f0` 完整 Release / CTest 3/3、Linux 22项 set测试及ASan/UBSan通过（malloc填充值165与255各一次）；Apple Silicon完整构建、CTest 3/3和19项set测试通过，仅验证功能，不提供性能数字。日志保存在远端 `final-verify/`。

审查了：空槽/Page对象生命周期、复用后的重新构造、页和叶恰好销毁一次、空集合释放全部slab；扩容/转换分配成功后才发布；新页首键走内联叶、不发生第二次分配；稠密未初始化槽所有读路径均先验证占用；删除清位和重插完整覆写；有符号边界、lower_bound及容量核算。外部依赖未全部sanitizer重编译。

作者未公布新版radix源码，当前仍是自主实现。作者9950X3D、数据/计时边界、五次取最快与这里不同；百万插入/查询/删除2.708/1.325/2.896 ns/op仅作[原文报告](https://zhuanlan.zhihu.com/p/2006092283301352464)参考，不能据此认定已复现或公平量化算法差距。
